## R1. 돌아보기 「달」 — 루틴마다 한 달

목업: `R1-A-카드.html`, `R1-B-띠.html`

### 공통
- 「주」 보기는 그대로예요. 「달」 보기만 바꿔요.
- 달 이름 줄(「‹ 2026년 11월 ›」) 오른쪽에 **보기 모양 전환**(작은 세그먼트, 아이콘 두 개)
  - 카드(네 칸 아이콘) · 띠(가로줄 아이콘), `aria-label` "카드로 보기" / "띠로 보기"
- **저장**: `users/{uid}.reviewMonthView: "card" | "strip"` — 기기마다가 아니라 사람마다 (폰 말고 다른 기기에서도 접속하므로)
- **기본값(아직 안 골랐을 때)**: 보이는 루틴이 **4개 이하면 카드, 5개 이상이면 띠**. 한 번 고르면 그 값을 따름
- 칸 상태 (두 모양 모두 같음)

| 상태 | 모양 |
|---|---|
| 해냄 | 루틴 주인 색 `--me` / `--her` (글자 `--me-ink` / `--her-ink`) |
| 못 함 | `--empty` / `--empty-text` |
| 쉬는 요일 · 루틴 만들기 전 날 | 빗금(`--line` 135도) |
| 오늘 이후 | 바탕 없이 `--line` 1px 테두리 |
| 오늘 | `--text` 2px 테두리 (오늘은 아직 '못 함'으로 치지 않음) |

- 「모두」 칸: 둘 다 그날 루틴을 모두 해냄 / 한 사람만 / 둘 다 못 함 → **루틴 탭 달력의 「모두」 규칙과 색(`--lv-full` / `--lv-half` / `--empty`)을 그대로** 써요. 목업의 `--both` 옅게는 자리만 잡은 것이에요.
- **%와 n/m은 '해야 했던 날' 기준**: 쉬는 요일 · 만들기 전 날 · 오늘 · 오늘 이후는 빼요.
- 루틴이 그 달 중간에 지워졌다면 지운 날 이후도 빗금으로 처리해요(가능하면).
- 저장 구조와 불러오기는 지금 n/m 막대와 같아요. 색인 추가 없음.
- 주 시작은 월요일(지금 돌아보기와 같음).

### A · 카드
1. 맨 위 「모두」 카드(`.card`): 제목 「모두」, 오른쪽에 "둘 다 해낸 날 **n일** / 지난 날 m일". 월~일 머리줄 + 큰 달력(칸 높이 30px, 숫자 있음) + 범례 한 줄
2. 사람별 묶음: 「● 준민」, 「● 단짝」 소제목 아래 **2칸 그리드**의 작은 카드
   - 카드: 루틴 이름(한 줄, 넘치면 …) → 작은 달력(칸 18px, 숫자 10px) → "✓ n/m · p%"
   - **320px 화면에서는 칸 숫자를 빼고 색만** (칸이 15px 안팎이 됨)
3. 맨 아래 범례: 해냄 · 못 함 · 쉬는 날/만들기 전 · 오늘 이후

### B · 띠
- 카드 하나 안에 줄이 쌓여요. 맨 위에 날짜 눈금(월요일 날짜와 1일만 숫자)
- 첫 줄 「모두」(오른쪽 "둘 다 n일"), 다음은 준민 루틴들, 단짝 루틴들 (줄 앞에 사람 색 점)
- 줄 = 루틴 이름 + 오른쪽 "n/m · p%" + 아래 30칸(또는 그 달 날짜 수) 띠, 칸 높이 22px, 숫자 없음
- **줄을 누르면** 바텀 시트로 그 루틴의 한 달 달력(A의 작은 카드를 크게 키운 것: 월~일 머리줄, 숫자 있는 칸, n/m · %) — 목업 없음, A 카드를 키운 모양으로
- 아래에 범례(준민 · 단짝 · 모두 · 못 함 · 쉬는 날)와 "숫자는 월요일 · 줄을 누르면 그 루틴의 한 달 달력"

### 테스트
- 보기 모양: 처음엔 루틴 4개 → 카드, 5개 → 띠. 한 번 바꾸면 `users/{uid}.reviewMonthView`에 저장되고 다른 기기에서도 그 모양
- 쉬는 요일 · 만들기 전 날은 %의 분모에서 빠짐 (예: 월수금 루틴, 11-19 기준 해야 했던 날 8일)
- 오늘 칸은 못 함으로 세지 않음, 오늘 이후 칸은 테두리만
- 「모두」 칸 색이 루틴 탭 달력과 같은 날에 같은 값
- B 줄을 누르면 그 루틴의 달력 시트가 열림
- 320px · 375px에서 넘침 없음, 14개 테마 스크린샷

## R2. 우리 지도 — 방문마다 각자 별점 + 메모

목업: `R2-C-다녀온곳시트.html`, `R2-기록남기기.html`
(`우리지도-구현.md` 5절 '시트: 다녀온 곳'과 6절 데이터를 이 내용으로 바꿔요)

### 바뀌는 뜻
- **별점은 지역에 한 번이 아니라 방문마다, 둘이 각자** 매겨요. 메모도 방문마다 각자 한 줄.
- **지역 별점 = 그 지역의 모든 별점 평균**(방문 · 사람 구분 없이 단순 평균). 소수 한 자리로 보여요.
  - 다녀온 곳 목록의 별 5개는 이 평균을 반올림해서 채워요.
  - 다녀온 곳 순위(별점 순) = 이 평균 → 같으면 다녀온 횟수 → 같으면 최근. **별점이 하나도 없는 곳은 맨 뒤**
- 별점은 방문 기록마다 선택이에요. 메모만 남겨도 되고, 별점만 남겨도 돼요.

### 시트: 다녀온 곳 (C · 접힌 목록)
1. 제목(지역 이름) + '함께 N번' 칩, "다녀온 곳 별점 N위 · 마지막 날짜"
2. **요약 카드**(`--raised`)
   - 왼쪽: 큰 평균 **4.1**(32px, 800) + 별 5개 + "별점 n개 평균"
   - 오른쪽(세로 구분선 뒤): 「● 준민 4.2 · 4번」, 「● 단짝 4.0 · 3번」 — 사람별 평균과 매긴 횟수
   - 별점이 하나도 없으면: "아직 별점이 없어요"
3. 버튼 두 개: **또 다녀왔어요**(채운 버튼) · **또 가고 싶어요**(테두리 버튼, → 순위 고르기). 좁은 폰에서 넘치면 세로로 쌓기
4. 「방문 기록」 목록 (최근 방문부터)
   - 접힌 줄(높이 52px 이상, `<button aria-expanded>`): 날짜 + " · N번째"(작게) · 오른쪽에 「● ★5」「● ★4」(사람 색 점 + 그 사람 별점, 없으면 「—」) · 펼침 화살표
   - 펼치면: 사람별 메모 칸 두 개(`--raised`, 12px 둥글기), 앞에 「● 준민」「● 단짝」
     - 내 칸이 비었으면 「+ 별점 · 한 줄 남기기」, 별점만 있으면 「+ 한 줄 남기기」 → 기록 남기기 시트
     - 단짝 칸이 비었으면 「아직 안 남겼어요」(`--sub`)
     - 내 칸을 누르면 기록 남기기 시트(고치기). 시트 안에 '방문 지우기'
   - 처음 열 때 **가장 최근 방문 하나만 펼쳐** 둬요.

### 시트: 기록 남기기 (또 다녀왔어요 · 내 기록 고치기 공통)
- 제목 「OO · 또 다녀왔어요」(고칠 땐 「OO · N번째 방문」), 아래 "내 별점과 메모만 남겨요. 단짝은 자기 칸을 따로 채워요"
- 다녀온 날(새 방문일 때만, 단짝이 된 날부터 — 기존 규칙 그대로)
- 내 별점: 별 5개 버튼(각 48px, `role="radiogroup"`), 같은 별을 다시 누르면 지움
- 한 줄 메모(선택), 한 줄 입력칸
- 안내 줄: "저장하면 단짝에게 '별점을 남겨 주세요' 알림이 가요" (새 방문일 때만)
- **저장**
- '함께 다녀왔어요'(안 간 곳 · 가고 싶은 곳 시트)를 누를 때도 같은 시트를 써요. 저장하면 지금처럼 가고 싶은 곳에서 빼고 뒤 순위를 당겨요.

### 알림
- 새 방문이 저장되면 단짝에게 푸시: 「OO 다녀온 기록이 생겼어요 · 별점을 남겨 주세요」 → 누르면 그 지역 시트
- 서버 함수(서울 리전): `places/{code}` 갱신 시 `visits`가 늘었고 만든 사람이 아닌 쪽에게만. 알림 시트에 스위치(`users.mapNudge`, 기본 켬)
- 단짝이 3일 안에 안 남겼을 때 다시 알리기는 하지 않아요(나중 후보).

### 데이터 (`places/{시군구코드}`)
```
places/{code}
  { code,
    wishRank, wishNote, wishedAt, wishedBy,          ← 그대로
    visits: [{ id, date: "YYYY-MM-DD", createdAt, createdBy }],   ← note 뺌
    entries: { <uid>: { <visitId>: { stars: 1..5|null, note: string, at } } },
    updatedAt, updatedBy }
```
- **지우는 것**: 지역 단위 `stars: { uid: n }`, `visits[].note`
- 평균 · 사람별 평균 · 순위는 **화면에서 계산**해요(지도 화면이 places 전체를 이미 구독함). 저장하지 않아요.
- 기록을 사람 기준(`entries.<uid>`)으로 두는 이유: Firestore 규칙은 배열 안을 하나씩 검사할 수 없어서, `visits[]` 안에 별점·메모를 넣으면 "자기 것만 고치기"를 막을 수 없어요.
- 방문 지우기: `visits`에서 빼고, 두 사람의 `entries.<uid>.<visitId>`도 함께 지워요. 둘 중 누구나 지울 수 있고, 지우기 전에 확인을 받아요. 방문이 0개가 되면 지도 색도 빠져요.

### `firestore.rules`
- `places`는 members 두 사람만 읽고 써요(그대로).
- `entries`가 바뀌는 쓰기: `request.resource.data.entries.diff(resource.data.entries).affectedKeys().hasOnly([request.auth.uid])`
  - 예외: 방문 지우기에서 상대 칸의 그 방문 기록을 함께 지울 때. 이 경우는 같은 쓰기에서 `visits` 길이가 줄어드는지 확인하거나, 지우기를 서버 함수로 처리해 주세요(구현 계정에서 더 단순한 쪽으로).
- `visits[].date`가 단짝이 된 날보다 이르면 막기(그대로).

### 옮기기 (한 번만, 스크립트)
- 기존 `stars.<uid>` → 그 사람의 **가장 최근 방문**의 `entries.<uid>.<visitId>.stars`
- 기존 `visits[].note` → `createdBy`의 `entries.<createdBy>.<visitId>.note`
- 옮긴 뒤 `stars`, `visits[].note` 필드 지우기. 옮기기 전에 백업(export)

### 테스트
- 평균: 별점 5, 4, 3, 4, 5, 5, 3 → 4.1, 준민 4개 · 단짝 3개 각자 평균
- 별점 없는 방문 기록(메모만)은 평균에서 빠짐. 별점이 하나도 없는 지역은 별점 순에서 맨 뒤
- 정렬: 평균 → 횟수 → 최근
- 규칙: 단짝의 `entries.<단짝uid>`를 내가 고치면 거부(에뮬레이터)
- 방문 지우기: 두 사람 기록이 함께 사라지고, 마지막 방문이면 지도 색 빠짐
- 옮기기: 옛 지역 별점이 가장 최근 방문으로, 옛 메모가 만든 사람 칸으로
- 시트: 가장 최근 방문만 펼쳐져 있음, 접힌 줄에 두 사람 별점(없으면 —)
- 새 방문 저장 → 단짝에게만 알림, `mapNudge` 끄면 안 감
- 320px에서 버튼 · 접힌 줄 넘침 없음, 14개 테마 스크린샷
