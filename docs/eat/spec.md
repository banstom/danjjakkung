# 출출 쿠키 — 명세 (spec)

> 기획 계정(claude.ai 「웹앱개발」) 2026-11-21. 처음 가제 「오늘 뭐 먹지」, 짝꿍 식탁을 대신하는 두 기능 중 하나(다른 하나는 오늘의 쪽지).
> 기준은 이 문서 + 고른 목업(`design/mockups/chosen/eat/`) + 참조 구현(`reference/`). 셋이 어긋나면 목업 → 이 문서 → 참조 순으로 맞추고 「바뀐 것」에 적기.
> 코드 · 파일 · 컬렉션 이름은 `eat` / `eats`(화면 이름만 「출출 쿠키」).

## 0. 한 줄
먹고 싶은 게 떠오를 때마다 쪽지에 적어 **쿠키에 넣어 두고**, 배고픈데 못 정하겠을 때 **미리 고른 개수(1 · 2 · 3)만큼 깨서** 하나 고른다. 단짝도 같은 통에 넣고, **서로의 쿠키는 깰 때까지 비밀**. AI 안 씀.

- 들어갈 자리: 「전체」 탭 우리 기능 칸, 2×2 (짝꿍 지도 · 오늘의 쪽지 · **출출 쿠키** · 단짝 영수증)
- 이름은 `text.js`의 `NAME` 한 곳. 화면 글은 전부 `makeText(NAME)`에서 (참조 `reference/src/text.js` — 목업 글과 글자 그대로)
- 단위는 「쿠키」, 동사는 쿠키 넣기 · 쿠키 깨기 · ○○로 할래요 · 먹었어요 · 통에 돌려놓기. 「쪽지」는 오늘의 쪽지와 겹쳐서 화면 글에 쓰지 않음(그림으로만)

## 2. 규칙

### 넣기 · 고치기 · 빼기
- 음식 1~20자(필수) · 메모 0~100자 · 가게 이름 1~40자. 글자 수는 보이는 글자 기준(이모지 1자). 앞뒤 공백 · 겹친 공백 정리
- 가게: 없음 / 이름만 / 카카오 장소(6절). 카카오 장소의 이름은 **사용자가 확인한 이름**으로 저장
- 작성 시각 = 서버 시각, 바꿀 수 없음. 고치면 「고침」 표시(`editedAt`)
- 고치기 · 빼기는 **적은 사람만, 통 안에 있을 때만**. 빼기는 지우지 않고 `state: 'out'`

### 깨기
- 개수 1 · 2 · 3 (마지막 고른 값과 범위를 `users/{uid}`에 기억, 처음엔 1 · 모두)
- 범위: 모두 / 내 쿠키 / 단짝 쿠키. 통 안(`jar`)에서만, **균등 무작위**, 중복 없이
- 고른 범위에 n개보다 적으면 있는 만큼. 0개면 깨기 버튼 꺼짐
- 「다시 뽑기」: 이번에 본 쿠키를 빼고 다시. 모자라면 본 것도 섞되 새 쿠키가 앞. 횟수 제한 없음
- 깨기 한 번 = `eatDraws` 한 줄(본 쿠키 · 고른 쿠키). 다시 뽑기는 같은 줄의 `shown`에 더함
- 고르지 않고 나가면 아무것도 안 바뀜(쿠키는 처음부터 통 안)

### 오늘 먹을 것
- **둘이 같이 하나** (`eatState/today`). 있는 동안은 깨기 버튼 꺼짐 + 「오늘 먹을 걸 정했어요. 다시 깨려면 먼저 먹었어요 또는 돌려놓기」
- 고르기 = 쿠키 `jar → today` + `eatState/today` 만들기를 **한 트랜잭션**. 이미 있으면 「단짝이 방금 골랐어요」 토스트 후 08로
- 돌려놓기 = `today → jar`(pick 지움) + `eatState/today` 지우기
- 다음 날부터 카드 머리가 「어제 고른 쿠키예요」 · 「그저께 고른 쿠키예요」. **고른 날부터 서울 날짜로 3일째**에 앱을 연 사람이 자동으로 돌려놓기(서버 함수 없음)
- 하루 기준은 서울 자정 (참조 `time.js` — 기기 시간대와 무관)

### 먹었어요
- 처음 누른 사람이 `today → eaten` + 자기 별점(1~5 정수) · 한 줄(0~40자) + `eatState/today` 지우기
- 단짝은 나중에 자기 별점 · 한 줄만 남김(자기 칸만). 목록의 평균은 매긴 사람만으로(소수 첫째 자리)
- 「단짝과 함께 먹었어요」(기본 켜짐) → `eaten.together`
- 「또 먹고 싶어요」(기본 켜짐) → 같은 내용의 새 쿠키를 같은 트랜잭션에(누른 사람이 적은 것으로, 작성 시각 = 지금, `from` = 먹은 쿠키). 목록에 「또 먹기 · 지난번 별점 ★4.5」
- 함께 + 카카오 장소 + 시·군·구 코드 있음 + 아직 안 칠한 시·군·구 → 저장 뒤 「짝꿍 지도에 성북구를 칠할까요?」 (참조 `mapAsk.js`, 7절)

### 비밀
- 단짝 쿠키는 **통 안에 있는 동안** 내용이 안 보임(깨서 봤다가 통으로 돌아온 것도 다시 비밀). 고른 뒤(today) · 먹은 뒤(eaten)는 보임
- 목록 함수는 비밀 줄에 음식 · 가게 · 메모를 **아예 넘기지 않음**(참조 `listRows`)
- 저장은 둘이 같은 `eats`를 읽음 — **화면에서만 숨김**(가정, 13절). 알림에도 메모는 안 넣음

## 3. 데이터 (Firestore)
```
eats/{id}       { food, place?: { name, kakaoId?, url?, sigungu? }, memo?, by, at, editedAt?,
                  state: 'jar' | 'today' | 'eaten' | 'out',
                  pick?: { by, at, drawId } | null,
                  eaten?: { at, by, together },
                  stars?: { [uid]: 1~5 }, notes?: { [uid]: string },
                  from?: eatId }
eatState/today  { eatId, by, at }                 ← 오늘 먹을 것 하나 (없으면 문서 없음)
eatDraws/{id}   { by, at, n, who: 'all'|'me'|'partner', shown: [eatId], picked?: eatId }
users/{uid}     eatDrawN · eatDrawWho · eatSeenAt  ← 마지막 개수 · 범위 · 입구 「단짝 +n」 기준(통 화면을 연 시각)
```
- 시각(`at` · `editedAt` · `pick.at` · `eaten.at`)은 **서버 타임스탬프**. 참조 구현은 계산을 쉽게 하려고 ms 숫자로 받음 → 저장소의 저장 계층에서 바꿔 넘기기
- 통 · 목록은 `eats`를 한 번 구독(onSnapshot)해서 메모리에서 거름(문서 수가 적음 — 한 해 수백 개). 결산은 나중에 따로
- `out`은 화면 어디에도 안 보임(결산에서만 셀 수 있게 남김)

## 5. 화면 부품 (새로)
- `cookie(who, open)` — 쿠키 그림(참조 `reference/src/cookie-svg.js`, 크기는 감싸는 요소의 `--s` 하나). 늘 `aria-hidden`, 뜻은 옆 글자가 전함
- 유리병(`.jar` — 뚜껑 · 목 · 몸통 · 하이라이트 · 개수 꼬리표, 쿠키는 정해진 13자리에 쌓고 넘치면 개수만 늘림), 펼친 쪽지(`.slip` — 오늘의 쪽지 5의 접힌 자국 종이), 오늘 먹을 것 카드(`.today`), 목록 줄(`.krow`), 별점(`.stars`, 44px 칸)
- 나머지는 기존 부품(카드 · 시트 · 세그먼트 · 칩 · 버튼 · 토스트 · 스위치 · 탭 바) 그대로. 목업의 CSS 이름은 참고용 — 저장소 부품 규칙에 맞춰 옮기기

## 6. 음식점 찾기 (카카오) — E5
```
앱 ─ 검색어 ─▶ Cloud Function searchPlace (서울 리전, members만, 한 사람 하루 100회 제한)
                 └ 카카오 로컬 「키워드로 장소 검색」 (음식점 FD6 · 카페 CE7) — REST 키는 Secret Manager
앱 ◀─ 후보 목록 ─ 하나 고름 → 이름 확인 → { name, kakaoId, url(place_url), sigungu } 저장
```
- **저장하는 것**: 장소 ID · place_url · 사용자가 확인한 이름 · 시·군·구 코드(5자리). 검색 결과의 장소명 · 주소 · 좌표는 저장하지 않음(보여 주는 동안만)
- **E5 전에 할 일**: 카카오 데브톡에 「시·군·구 코드를 저장해도 되는지 · 장소명을 기본값으로 채워도 되는지」 문의(구현 계정 앱 ID로). 답이 오기 전에는 시·군·구 저장과 지도 칠하기 물음을 끔
- 시·군·구 코드: 결과 주소의 시·도 + 시·군·구 이름을 `data/kr-map.json` 이름과 맞춤. 2026-07 행정구역 개편(인천 · 전남광주 · 안양)이 지도 데이터와 맞는지 확인
- 무료 쿼터 · 바뀐 사용 방법(2026-07-21~)은 키 발급 때 공지 다시 확인
- E5 전 03 시트: 검색 칸 없이 「이름만 적기」만 (목업 03의 맨 아래 줄)

## 7. 짝꿍 지도 연결
- 먹었어요 시트를 저장한 뒤 조건(2절)이 맞으면 확인 시트 「짝꿍 지도에 ○○구를 칠할까요?」 → 예: 그 시·군·구에 방문 기록(그날 날짜, 메모 = 음식 이름) — 지도 기능의 「다녀왔어요」와 같은 쓰기
- 칠한 시·군·구 목록은 지도 기능이 가진 것을 읽기만

## 8. 꿍 알림
- 08 「꿍으로 알려 주기」 = 기존 꿍 보내기에 이 글을 붙여 보냄: 제목 「단짝이 출출 쿠키를 깼어요」, 본문 「오늘은 김치찌개 어때요?」(`pushTitle` · `pushBody`). 메모 · 가게는 안 넣음
- 꿍에 글을 붙일 수 없는 구조면 이 기능 전용 알림으로 보내고 「바뀐 것」에 적기
- 단짝이 쿠키를 넣을 때는 알림 없음 → 입구 칸 「단짝 +n」만

## 9. 쿠키 그림 · 색 (가이드라인 예외)
- 그림: **C 스티커 · 금빛** (11-21 사용자 고름). 모양 숫자는 바꾸지 않기
- **그림 전용 토큰 5개 + 1** — 토마토(`--tomato-*`)와 같은 예외로 가이드라인 문서에 먼저 적기:
  `--ck-hi --ck --ck-mid --ck-dk --ck-ol` (쿠키) · `--ck-paper` (쿠키 안 쪽지)
- 값(초안 `design/components/cookie/art.css`): 밝은 판 = 소프트 파스텔 값, 어두운 판 = 코스믹 드림 값을 기본으로 **14판 모두**에 채우기. 도트 테마도 일단 같은 값(도트 쿠키는 나중 후보)
- 쿠키 그림 말고 화면 색은 기존 토큰만. 빨강(`--warn`)은 빼기 확인 · 오류에만

## 10. 움직임
- 05 깨기: 쿠키마다 0.3초 간격 · 각 0.35초(갈라짐 → 쪽지 올라옴). 누르면 바로 끝. `prefers-reduced-motion: reduce`면 움직임 없이 06
- 04 넣기: 종이가 접혀 병으로 들어가는 0.4초 + 병 안 새 쿠키 1초 빛남. 줄이기 설정이면 토스트만

## 11. 접근성
- 쿠키 그림은 장식(`aria-hidden`). 병은 `role="img"` + 「쿠키 통, 쿠키 12개」
- 06 고르기 줄은 `button` + `aria-pressed`. 별점은 버튼 5개 + 「별 n개」. 터치 칸 44px 이상
- 글자 대비 4.5:1 (어둡게 포함)

## 12. 결산 (나중)
- 후보: 이번 달 깬 쿠키 n · 가장 많이 나온 음식 · 함께 먹은 곳 — 결산 구상과 맞춰 정함. 이번 단계에 넣지 않음

## 13. 가정 (기획 계정이 정한 것 — 사용자 확인 전)
- 고른 쿠키는 서울 날짜로 3일째 자동으로 통에 돌려놓기
- 비밀은 화면에서만(규칙으로 막으려면 내용을 하위 문서로 나눠야 함 — 필요해지면 따로)
- 단짝이 쿠키를 넣을 때 알림 없음
- 한 번에 1~3개
- 「또 먹고 싶어요」 · 「단짝과 함께 먹었어요」 기본 켜짐
