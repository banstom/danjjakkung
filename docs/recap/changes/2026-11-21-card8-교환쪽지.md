- 식탁 계산(끼니 · 목표 맞춘 날)은 **만들지 마세요**. 데이터가 생길 일이 없어요.

## 3. 카드 8 「교환 쪽지」 명세

### 3-1. 데이터 (교환 쪽지 spec 그대로)
```
qdays/{date}          { text(그날 질문), done: { uid: ts }, likes: { uid: true }, ... }   ← date = 서울 날짜 'YYYY-MM-DD'
qdays/{date}/a/{uid}  { text(쪽지), at, editedAt? }
```
- `likes[L] = true` = L이 그날 **상대의 쪽지**를 「마음에 남아요」로 담았다는 뜻 (둘 다 남긴 날에만 누를 수 있음)

### 3-2. 계산 (`changes/card8/src/note-card.js`의 `computeNoteCard`)
- **둘 다 남긴 날** = 기간 안 `qdays` 중 `done`에 두 사람 uid가 다 있는 날의 수. 질문 날짜 기준이라 **늦게 남긴 쪽지도 그 날짜로** 세요(결산을 계산하는 순간까지 남긴 것)
- **가장 긴 연속** = 둘 다 남긴 날이 달력 날짜로 이어진 가장 긴 길이
- **지난달 비교**(월말만) = 이번 달 − 지난달. **지난달 `qdays`가 하나도 없으면 비교 없음**(`null`, 칩 안 보임) — 기능이 생긴 첫 달에 「+15일」이 뜨지 않게
- **마음에 남은 쪽지**
  - 셈: 둘 다 남긴 날의 좋아요 수 (작성자 쪽지 글이 비었으면 안 셈)
  - 보여 주기: **누른 사람마다 가장 최근 한 장, 최대 2장, 최근 날짜 순**. 작성자 글이 비어 있으면 그 사람의 다음으로 최근 날
  - 한 장 = { 날짜, 그날 질문, 쪽지 글(앞뒤 빈칸 뗌, 300자까지), 작성자 uid, 누른 사람 uid }
- **건너뛰기**: 둘 다 남긴 날이 0이면 `null` → 카드 없음, 진행 막대 칸도 하나 줄어요
- 모든 날짜는 문서 id 문자열로만 다뤄요(시각 계산 없음 → 서울/기기 시간대 문제 없음)

### 3-3. 화면 (목업 `08-교환쪽지.html`, 시안 A 꽉 찬 색 그대로)
위에서부터
1. 머리 「교환 쪽지」 (기능 이름은 교환 쪽지 `text.js`의 `NAME`을 받아 씀)
2. 큰 숫자 「15일」
3. 비교 칩 「지난달보다 +3일」 / 「지난달보다 −2일」 / 「지난달과 같아요」 — **카드 2와 같은 칩 · 같은 규칙**(빨강 없음, 마이너스는 U+2212). 카드 2에 「같음」 문구가 따로 있으면 그걸 따라 주세요
4. 설명 「둘 다 쪽지를 남긴 날이에요.」 + (연속 2일 이상일 때만) 「가장 길게는 n일 연속」
5. 「마음에 남은 쪽지 n장」 + 쪽지 카드 1~2장
   - 머리: ♥ 「준민의 마음에 남은 쪽지 · 11월 15일 (일)」 (누른 사람)
   - 그날 질문 (`--sub`, 낱말 단위 줄바꿈)
   - 쪽지 글 (15px, **3줄까지, 넘치면 …**)
   - 작성자: 사람 색 점 + 「단짝의 쪽지」
   - 모양: `--surface` 카드, 오른쪽 위 모서리만 작게 접힌 모양(교환 쪽지 질문 카드의 접힌 모서리와 같은 결). 쪽지 모양 5 전체를 옮기지는 않아요(카드 9 영수증만 종이 모양이라는 결산 규칙 유지)
   - 마음에 남은 쪽지가 없으면 5번 전체를 빼요
- 사람 이름은 **보는 사람 기준**(나 = 내 이름, 상대 = 「단짝」) — 결산 다른 카드와 같아요. 저장은 uid로
- 가장 긴 경우(질문 42자 + 쪽지 두 장 3줄 + 연말 칸)도 390 · 320px에서 넘치지 않는 것을 기획 계정에서 확인했어요

### 3-5. 연말 (목업 `Y-08-교환쪽지.html`)
- 1년치 둘 다 남긴 날 · 가장 긴 연속(달을 넘어 이어짐) · **가장 많이 주고받은 달**(같으면 앞선 달) 칸 — 카드 2 연말의 「가장 잘 해낸 달」 칸과 같은 모양
- 비교 칩 없음
- 마음에 남은 쪽지: 1년 전체에서 같은 규칙(사람마다 가장 최근 한 장, 최대 2장)

### 3-6. 마무리(카드 10) · 이미지 저장
- 여섯째 타일이 「쪽지를 주고받은 날」로 바뀌어요(목업 `10-마무리.html`)
- **이미지(1080×1920)에는 숫자만.** 쪽지 글 · 질문은 이미지에 절대 넣지 않아요 — 이미지는 밖으로 공유될 수 있어서. `noteTile()`이 숫자만 돌려줘요

## 4. 서버 함수 (`monthlyRecap`)
- `qdays`를 **문서 id 범위**로 읽기: 이번 달 `'2026-11-01' ≤ id < '2026-12-01'`, 지난달도 같은 방식 (연말은 1년). 색인 추가 없음
- 마음에 남은 쪽지 후보 날(좋아요가 있는 날)에만 `qdays/{date}/a/{작성자uid}`를 읽기 — 한 달에 많아야 수십 번
- 결과는 지금 결산 문서 규칙대로 카드 칸에 저장 (예: `recaps/{YYYY-MM}.cards.note = { bothDays, streak, prevDiff, likedCount, liked[], bestMonth? }`). **결산 뒤에 쪽지를 고쳐도 결산은 그대로**(기존 규칙)
- `recaps`는 두 사람만 읽고 클라이언트는 못 쓰는 기존 규칙 그대로. 쪽지 글이 결산 문서에 들어가지만, 그 쪽지는 두 사람이 이미 서로 본 것(둘 다 남긴 날)이라 보이는 범위가 넓어지지 않아요
- 결산 알림(1일 9시) 문구에 쪽지 내용은 넣지 않아요

## 5. 기획 계정이 가정으로 정한 것 (확인 필요)
- 마음에 남은 쪽지는 **사람마다 가장 최근 한 장** (대안: 가장 처음 · 무작위)
- 쪽지 글은 **3줄에서 자르기** (대안: 다 보이기 — 길면 카드가 넘침)
- 지난달 기록이 없으면 비교 칩 숨김
- 카드 위치는 식탁 자리 그대로 8번
