### ③ 짝꿍 식탁
- 머리말: 날짜 ▾(누르면 ③-1) · 제목 "짝꿍 식탁" · 오른쪽 위 ⚙ · +
- [준민 | 단짝] 전환 → **목표 대비 요약**과 **아래 끼니 목록**이 그 사람 것으로 바뀜. 차트는 늘 둘 다
- **목표 대비 요약**: 칼로리 · 탄수 · 단백질 · 지방, 막대 + "실제 / 목표" + 문구 (`goals.md` 6절)
- **거울 차트**: 6~24시, 가운데 시간 띠 위로 내 기둥 · 아래로 단짝 기둥, 높이 = 끼니 kcal
  - 탄단지 = 사람 색 진하기 (띠 쪽부터 탄수 진하게 → 단백질 → 지방 연하게). 진하기는 `color-mix(in srgb, var(--me) 58%/28%, var(--surface))`
  - 정확한 비율은 기둥을 누르면 말풍선: `12:40 점심 · 1,552kcal / 탄 59% · 단 16% · 지 25%`
  - 함께 먹은 끼니 = 위아래 기둥 뒤 함께 색(`--both` 30%) 배경, 시각은 띠에 함께 색 칩으로 한 번만
  - 기둥 위 kcal, 띠 안에 먹은 시각
- **끼니 목록**: 그 사람 것만, 줄마다 탄·단·지 g, 줄 사이에 "공복 ○시간 ○분", 맨 위 "아침 전 공복"(전날 마지막 끼니가 있으면, 없으면 '어제 기록 없음'). 함께 먹은 끼니에 함께 칩
- 사람 색: 나 `--me`, 단짝 `--her`, 함께 `--both`. 빨강은 쓰지 않음

## 정한 것
- **3단 구조**: 끼니(시각 · 식사/간식) → 항목(무엇을 · 얼마나) → 재료(구성 성분)
- **레시피는 한 번만 적기**: 저장해 두고 이름 + 양만 적으면 계산. 양만 바꿔 적으면 그 끼니에만 덮어씀
- **내 단위 등록**: 내 기준 g으로. 새로 정한 단위는 앞으로만 적용 — 사용자 값: 한 공기 = 햇반 1.5개 = 315g
- **꼭 필요한 것만 되묻기**: 추정 칼로리 범위가 80kcal 이상 벌어지는 것만, 최대 3개 (`tests.md` 2절)
- 탄수 · 단백질 · **지방**까지 계산
- **보충제**(크레아틴 등)는 영양 합계 대신 '먹었나' 체크. 루틴 체크와 연결 후보
- **목표**: `goals.md`
- **보여주기**: 식단 · 목표 숫자 · 레시피·식품은 단짝과 공유 / 몸 정보 · 체중 기록은 나만 / 내 단위는 사람마다 따로
- **같이 먹은 끼니: 한 사람이 적으면 둘 다에게** (`by: "both"` + `share`). 기본은 같은 양, 다르면 확인 카드에서 사람별로
- **수면 기록은 넣지 않음**. 표기: '공복 시간', 시간은 `4시간 20분` 꼴

## AI 처리
```
앱 ─ 적은 글 ─▶ ① 앱 코드: 저장된 레시피·식품·단위로 맞춰 보기 (AI 안 씀)
                ② 못 맞춘 줄만 Cloud Function parseMeal (서울 리전, members만)
                   └ LLM API (키는 Secret Manager) → 정해진 JSON 모양 (`tests.md` 1절)
앱 ◀─ 정리 결과 + 질문 1~3개 ─ 확인 카드 → 저장
```
- **API 키는 앱 코드에 넣지 않음**. 서버 함수에서만. 몸 정보는 보내지 않음
- **AI가 하는 일**: 처음 보는 음식 구조 나누기, 저장된 것과 짝짓기, 모르는 것 목록. **영양 숫자는 AI가 내지 않음**
- **앱 코드가 하는 일**: 숫자 꺼내기, 합계 · 레시피 비율 · 탄단지 kcal 비율 · 공복 시간 · 목표 계산 · 목표 대비 · 다시 맞추기 제안, 질문 고르기
- **먼저 저장, 나중에 정리**: 시각과 원문은 바로 저장(status: pending), AI 결과는 나중에 채움
- 시판 제품 영양값은 사진(영양성분표) 또는 직접 입력으로 한 번만 (AI가 지어내지 않게)
- 요청 횟수 제한(하루 n회)
- 모델: Claude Haiku 5.5 / Gemini 중 시험 A로 돌려 보고 정함 (아래 비용)

### AI 비용 (11-17 조사)
- 한 번 ≈ 입력 4,000 + 출력 1,000 토큰, 둘이 한 달 300번 (1달러 ≈ 1,400원)
  - Claude Haiku 5.5($0.10 / $0.50 per 1M): 약 400원 · Gemini 3.1 Flash-Lite($0.25 / $1.50): 약 1,000원 · Gemini 3.8 Flash($0.75 / $3.75, 2027-01부터 두 배): 약 2,800원
- Gemini 무료 등급: 한도가 크게 줄었고 결제 연결 안 된 별도 프로젝트 키가 필요, 요청이 Google 제품 개선에 쓰일 수 있음
- Claude API는 claude.ai 구독과 별도로 Anthropic 콘솔에서 크레딧 충전

## 데이터 (단짝꿍 구조에 맞춤, 안)
```
meals/{id}     { by: uid | "both", share?: { uid: 비율 }, at, kind: "meal"|"snack", raw, status,
                 items: [{ name, amount, unit, refId?, ingredients?, overrides?, kcal, carb, protein, fat, confidence }] }
foods/{id}     { type: "recipe"|"product"|"supplement", name, per100g | ingredients, servings, memo?, by, updatedBy }   ← 둘이 함께 씀
users/{uid}    units: { 공기: { g: 315, set: "user" }, ... }, foodUnits?: { foodId: { 줌: 20 } },
               goal: { kind: "cut"|"keep"|"bulk", kcal, carb, protein, fat, edited: bool, retune: bool }   ← 둘 다 읽음
private/{uid}  { body: { sex, age, heightCm, weightKg, activity }, suggested: {...}, ackAt }               ← 본인만
private/{uid}/weights/{date}  { kg }                                                                     ← 본인만, retune 켰을 때만
```
- **보안 규칙**: `private/{uid}` 와 그 아래는 `request.auth.uid == uid` 만 읽고 씀. 나머지는 지금처럼 members 두 사람
  - Firestore 규칙은 문서 단위라 필드 하나만 숨길 수 없음 → 몸 정보는 문서를 나눔
  - 추천값 계산은 본인 기기에서 하고, 목표 숫자만 `users/{uid}.goal`에 저장
- 식단 화면을 열 때만 meals를 읽음(그날 범위). 실시간 반영은 짝꿍 식탁이 열려 있을 때만
