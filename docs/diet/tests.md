# 짝꿍 식탁 — AI 정리 시험 · 계산 시험 (2026-11-17 실제 기록)

> 함께 볼 문서: `plan.md` · `goals.md` · `fixtures/day-2026-11-17.json` · `fixtures/foods.json`
> 목적: 정리 모델(Haiku 5.5 등)이 충분한지 확인하고, 모델·지시문을 바꿀 때마다 같은 시험으로 다시 확인하는 회귀 테스트

## 0. 시험을 둘로 나눔

| 시험 | 무엇을 보나 | 맞았는지 판단 |
|---|---|---|
| **A. AI 정리 시험** | 글 → 구조(JSON). 시각 · 식사/간식 · 항목 · 양 · 단위 · 짝짓기 · 모르는 것 | 아래 "꼭 맞아야 하는 값"이 **정확히** 같아야 함. 이름 표기·순서·메모는 달라도 됨 |
| **B. 계산 시험** (AI 없음) | 구조 + 기준 식품값 → 합계 · 레시피 비율 · 공복 시간 · 질문 고르기 | 아래 기대값과 ±0.1 |

- AI는 **숫자(영양값)를 내지 않는다.** 짝짓기와 모르는 것 목록만 낸다. 숫자는 식품표·내 식품에서 앱 코드가 꺼냄
- B는 `npm test`로 (`fixtures/`를 그대로 씀), A는 실제 모델을 부르는 별도 시험(`npm run test:ai`)

## 1. AI 출력 모양 (안)

```json
{
  "meals": [{
    "at": "08:20",                 // 24시간 "HH:MM"
    "kind": "meal",                // "meal" | "snack"
    "label": "아침",               // 있으면
    "items": [{
      "name": "셀프메이드 브라우니",
      "amount": 9, "unit": "조각",
      "portion": { "num": 9, "den": 16 },          // 레시피 일부를 먹었을 때만
      "match": { "kind": "new_recipe" },           // "table" | "food" | "new_recipe" | "new_product" | "supplement"
      "ingredients": [
        { "name": "바나나", "amount": 2, "unit": "개", "match": { "kind": "table", "key": "바나나" } },
        { "name": "무당초콜릿", "amount": 2, "unit": "줌", "match": { "kind": "new_product" } }
      ],
      "overrides": [],                              // 저장된 레시피에서 바뀐 재료만 (T6)
      "memo": "오븐 170도 25분"
    }]
  }],
  "unknowns": [                                     // 모르는 것. 묻을지 말지는 앱이 정함
    { "path": "아침/셀프메이드 브라우니/무당초콜릿", "what": "product_and_grams", "kcalRange": [0, 300] }
  ],
  "learn": []                                       // 정정 답에서 저장할 것 (T3, T7)
}
```

## 2. 질문 고르기 규칙 (앱 코드)
- `kcalRange` 폭이 **80kcal 이상**인 것만, 폭이 큰 순서로 **최대 3개**
- 이 규칙이면 11-17에 실제로 물은 3개(밥 · 초콜릿 · 기름)가 나오고, 오뎅국(폭 60) · 갓김치 · 프로틴 종류는 안 물음
- 저장된 레시피에 있는 재료는 모르는 것이 아님 → 말 안 한 재료는 레시피 값 그대로 (T6)
- 사용자가 아직 정하지 않은 내 단위(기본값 사용 중)는 모르는 것 → 정하면 다시 안 물음 (T7)

## 3. 기준 식품값 → `fixtures/foods.json`
- 실제 앱에서는 식약처 식품영양성분 DB로 바꾸되, **시험은 이 고정값으로** 돌린다 (DB가 바뀌어도 시험이 흔들리지 않게)

## T1. 아침 — 처음 쓰는 상태


**A. 꼭 맞아야 하는 값**
- 날짜 2026-11-17, 끼니 1개: `at "08:20"`, `kind "meal"`
- 항목 3개

  - 사과: 1 개, `table:사과`
  - 브라우니: 9 조각, `portion 9/16`, `new_recipe`, 재료 4개

- 다음 줄의 `:( … )`가 바로 위 항목(브라우니)의 재료로 붙어야 함 (따로 항목이 되면 실패)
- unknowns에 꼭 있어야 함: ① 무당초콜릿(제품·g) ② 스크램블 조리 기름(입력에 없지만 스크램블이라 추정)

## T3. 정정 답 — 말로 고치기

**시작 상태**: T1 · T2 저장됨, 질문 3개를 보여 준 뒤

**입력** (실제 답을 줄인 것)
```
스크램블 할 때 카놀라유를 사용했고, 밥은 햇반보다는 좀 더 많은 것 같다.
그냥 내가 그 밥으로 먹은 양을 햇반 3공기로 볼게.
무당 초콜릿은 파베글라스 설탕무첨가 다크 루미에르 초코칩, 400g, 1개. 두 줌이면 40g 정도 될듯
```

**A. 꼭 맞아야 하는 값**
- 고칠 곳 3개
  - 아침/달걀스크램블 ← 재료 추가 `카놀라유`, 양 없음 → 기본 1스푼으로 두고 unknowns에 남김(폭 80 미만이라 다시 묻지 않음)
  - 점심/특 간계밥/밥 ← `햇반 3개` (= 630g)
  - 아침/브라우니/무당초콜릿 ← 제품 `파베글라스 설탕무첨가 다크 루미에르 초코칩`, 40 g
- learn (저장할 것)
  - 레시피 `특 간계밥`의 밥 = 630g
  - 내 식품(제품) `파베글라스 … 초코칩` 등록 요청 → 영양값은 사진/직접 입력으로 받음(AI가 지어내면 실패)
  - "두 줌 = 40g" → 이 제품의 `줌 = 20g`
- **하면 안 되는 것**: 내 단위 `공기`를 바꾸지 않음 (사용자가 "공기 크기"가 아니라 "이 밥의 양"으로 답했음)
- "400g, 1개"는 포장 크기라서 먹은 양이 아님 (40g을 400g으로 읽으면 실패)

## T7. 늦은 식사 — 내 단위 "공기" 정하기 (실제 11-17 22:30)

**시작 상태**: T1~T6 저장됨, 내 단위 `공기`는 아직 기본값(210g, 사용자가 정한 적 없음)

**입력 ①**
```
2230에 식사: 밥 1.5공기 / 조기 1개 /김치꽁치찌개 /멸치볶음
```

**A. 꼭 맞아야 하는 값 ①**
- 끼니 1개: `at "22:30"`, `kind "meal"`
- 항목 4개: `/`로 나눔
  - 밥 1.5 공기 `table:햇반` (공기 → 내 단위)
  - 조기 1마리 `table:조기구이` ("1개" → 마리)
  - 김치꽁치찌개 1인분 `table` / 멸치볶음 1접시 `table`
- unknowns: ① 밥(공기 크기, 기본값 사용 중) ② 김치꽁치찌개 양(150~300)
- 질문 고르기 결과: **밥 · 찌개** 2개 (둘 다 폭 80 이상)

**입력 ② (답)**
```
내 한공기=햇반1.5개
```

**A. 꼭 맞아야 하는 값 ②**
- learn: 내 단위 `공기 = 315g` (햇반 1.5개 × 210g)
- 22:30 밥 → 1.5공기 × 315g = **472.5g** (햇반 2.25개)
- **이전 기록은 바꾸지 않음**: 점심(밥 630g, T3에서 직접 정함) · 18:15 저녁(햇반 기준이라고 적음)은 그대로
- 찌개 질문에 답이 없으면 기본값 1인분으로 두고, 다시 묻지 않음
- 이후 "밥 1공기"는 질문 없이 315g
