# 겨울 업데이트 테마 — 시험 목록

> `npm test`에 넣을 것. 화면 시험은 지금처럼 Playwright 모바일(390×844, 터치), 요소는 선택자 · 접근성 트리로 찾기(좌표 어림 금지).

## A. 토큰 · 색
- **A1** 네 판(`winter-snack` `winter-snack-night` `merry-xmas` `merry-xmas-night`)이 토큰 목록의 모든 토큰을 정의 (기존 '토큰 이름' 시험에 네 판 추가)
- **A2** 글자 대비 검사에 네 판 추가 — `contrast.md`의 21쌍 모두 4.5:1 이상
- **A3** CSS · JS에 hex가 새로 생기지 않음. `themes/**/*.svg`와 PNG는 검사 제외 목록에
- **A4** 빨강 검사: `--warn` 밖의 빨강은 그림 파일 안에만

## B. 낮 · 밤 판 고르기
- **B1** 테마 `winter-snack` + 모드 `auto` + 시스템 밝게 → `data-theme="winter-snack"`, 어둡게 → `winter-snack-night` (`emulateMedia({ colorScheme })`)
- **B2** `auto`인 채로 시스템을 밝게 → 어둡게 바꾸면 새로고침 없이 바로 밤 판
- **B3** 모드 `light` 고정이면 시스템이 어두워도 낮 판, `dark` 고정이면 반대
- **B4** `modes`가 없는 테마(`soft-pastel`)는 모드 값과 관계없이 그대로, 설정 화면에 「자동 · 낮 · 밤」 줄이 없고 안내 한 줄이 있음
- **B5** 테마를 안 고른 사용자는 지금과 같음 (밝게 `soft-pastel` / 어둡게 `cosmic-dream`)
- **B6** **첫 프레임**부터 맞는 `data-theme` · `data-skin` (밤에 앱을 열 때 낮 판이 한 프레임도 안 보임 — 회귀 9번과 같은 방식)
- **B7** 저장값 `danjjakkung.theme = "winter-snack-night"`(판 id) → `winter-snack`으로 고쳐 저장, 화면은 정상
- **B8** 모르는 테마 id → 기본 테마, 화면 그리기 실패 없음 (회귀 10번과 같은 규칙)
- **B9** 모드 값이 이상하면(`"dusk"` 등) `auto`로

## C. 픽셀 스킨
- **C1** 도트 테마에서만 `data-skin="pixel"`. 다른 테마로 바꾸면 속성이 사라지고 카드 모서리 · 글꼴이 원래대로
- **C2** Galmuri 글꼴 파일은 도트 테마일 때만 내려받음 (다른 테마에서 네트워크 요청 0)
- **C3** 도트 테마에서 글꼴이 실제로 불러와짐 (`document.fonts.check`)
- **C4** 픽셀 스킨의 글씨 크기가 spec.md 4절 표의 값(고유 크기의 정수배)만 쓰임
- **C5** 머리 장식이 머리말 글자를 가리지 않음 (머리말 위쪽 여백 ≥ 장식 높이)
- **C6** 세그먼트 · 버튼 · 탭의 누를 자리 44px 이상 유지

## D. 그림 S1~S4
- **D1** 고른 테마의 그림만 내려받음 (도란도란에서 크리스마스 그림 요청 0)
- **D2** 그림 크기 = 원본 × 정수 배율 (`img.width / img.naturalWidth`가 정수), `image-rendering: pixelated`
- **D3** 그림이 없는 테마에서는 자리 요소가 없음 (화면이 지금과 같음 — 기존 화면 비교 시험 통과)
- **D4** 테마 그림 합계 ≤ 150KB
- **D5** 낮 · 밤 판에서 같은 그림 파일을 씀

## E. 설정 화면
- **E1** 「테마·사람 색」 열기 → 「자동」이 눌린 상태, 아래 줄 문구가 지금 판과 맞음
- **E2** 테마 카드를 누르면 바로 적용, `사용 중` 꼬리표가 옮겨감, 저장값 바뀜
- **E3** 「두근두근 크리스마스」 이름이 낱말 가운데서 줄바꿈되지 않음 (`word-break: keep-all`)
- **E4** 사람 색은 지금처럼 동작 (기존 시험 통과)
- **E5** 밤 판에서 이 화면의 글자 대비 (A2로 확인)
