- **다른 테마 화면은 바뀌면 안 됨** (TS1의 시트 화면만 바뀜)
- 화면을 새로 그려야 하면 구현하지 말고 기획 계정에 목업 요청

## 4. 구현 계정에 맡길 말
처음 (TS1):
```text
docs/themes-2026-11/README.md를 먼저 읽고 전체 단계를 파악해 줘. 저장소의 AI 작업 가이드라인을 따라 줘.
main에서 모음 브랜치 themes-2026-11을 만들고, 거기서 따서 TS1을 해 줘 (docs/themes-sheet/README.md · spec.md · tests.md · 목업).
지금 있는 테마만으로 시트를 C안으로 바꾸고, 다른 화면은 하나도 바꾸지 마. 끝나면 npm test 결과, 바꾼 파일, 문서와 다르게 정한 것을 알려 줘.
```
다음 단계마다 (SA1 → OT1 → TC1 → AO1):
```text
docs/themes-2026-11/README.md 3절의 다음 단계 ○○1을 해 줘. 그 폴더 README · spec · 목업 · tokens · pixel-skin · tests를 먼저 읽고,
앞 단계에서 만든 판 묶음 · 도트 스킨 · 그림 자리 · 시트 묶음을 그대로 써 줘. 모음 브랜치 themes-2026-11에서 따서 하고 끝나면 그리로 합쳐 줘.
끝나면 npm test 결과, 바꾼 파일, 문서와 다르게 정한 것을 알려 줘.
```

## 5. FIN — 마지막 점검 · 배포
1. **점검 AI** (새 세션):
```text
docs/themes-2026-11/ 아래 문서와 docs/themes-*/ 폴더들, 그리고 themes-2026-11 브랜치를 비교해서 문제만 목록으로 적어 줘. 코드는 고치지 마.
특히: 기존 테마 화면이 바뀌지 않았는지, 테마 시트가 C안(묶음 순서 · 펼침 규칙 · 이번 달 표)대로인지, 그 테마가 아닐 때 그림 · 장식을 내려받지 않는지,
그림이 정수 배율로만 그려지는지, 22판 모두 대비 4.5:1, 버튼 글자가 --on-primary인지(테니스 · 공항 낮, 캠핑 밤은 진한 글씨),
색이 토큰만 쓰는지(그림 · 장식 파일 제외), 밤에 열 때 낮 판이 한 프레임도 안 보이는지, 규칙 validColors에 새 사람 색 88개가 다 들어갔는지.
```
2. 나온 문제 고치기(고칠 때마다 회귀 시험) → 폰에서 각 폴더 `tests.md` 「손으로」 + 목업 대조
3. `themes-2026-11` → main 합치기 (화면 배포) **+ 같은 날 Cloud Shell에서 규칙 배포** (`bash scripts/redeploy.sh` 등 지금 쓰는 방법)
- 사람 색 후보: 여름 · 가을 16 + 천문대 · 기차 16 + 테니스 · 도시 32 + 공항 · 나들이 24 = 88색 (겹치는 색은 한 번만)
