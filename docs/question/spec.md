# 교환 쪽지 (코드 이름 question) — 구현 문서

> 기획 계정(claude.ai 「웹앱개발」)에서 정한 내용이에요. 구현 계정은 이 문서 · `reference/` · `rules/` · 목업을 기준으로 삼아 주세요.
> 목업 캔버스(기획 계정): https://claude.ai/artifact/QapnTbAZWHE4t3zL3on4PR — 묶음의 `design/mockups/chosen/question/`에 고른 화면(HTML + PNG)
> **이름은 「교환 쪽지」** (11-21 사용자 결정, 처음 가제 「오늘의 질문」). 화면 글은 '답' 대신 '쪽지'로 부르고, 데이터 · 코드 이름(`qdays` · `a/{uid}` · answer)은 그대로예요.
> 가이드라인 그대로: 작은 모듈, 색은 토큰만, Pretendard · Tossface, 버그마다 회귀 시험, 배포 전 점검 AI.
> 이 기능은 **짝꿍 식탁을 대체**해요. 식단 넘기기 묶음(`docs/diet/`)의 D단계는 진행하지 않아요.

## 0. 한 줄 요약
하루에 질문 하나, 둘 다 답해요. **내가 답해야 단짝 답이 열려요.** 질문은 기본 묶음 414개 + 날짜 질문 + 우리가 넣는 질문에서 정해진 규칙으로 하나씩 나와요. AI는 쓰지 않아요.

## 3. 데이터
최상위 컬렉션(지금 저장소 방식). 이름이 겹치지 않게 `qdays` · `ourQuestions`.
```
qdays/{YYYY-MM-DD}                         ← 그날 질문 (서울 날짜)
  { q,            // 질문 id: 기본 'daily-012' · 우리 'o-…'(ourQuestions 문서 id) · 날짜 'first' | 'anniv:1' | 'hundred:300' | 'date:12-25'
    text,         // 그날 보여 준 문장 (나중에 원본을 고쳐도 기록은 그대로)
    src,          // 'base' | 'ours' | 'date'
    by,           // 우리 질문이면 낸 사람 uid, 아니면 null
    skipped: [],  // 「다른 질문」으로 넘긴 질문 id
    swappedAt?, swappedBy?,
    done: { uid: Timestamp },   // 답한 사람 표시 (답 글은 아래 문서에)
    likes: { uid: true },       // uid가 단짝 답에 「마음에 남아요」
    createdAt }
qdays/{date}/a/{uid}   { text(1~300자), at, editedAt? }     ← 사람마다 문서 하나
ourQuestions/{id}      { text(2~60자, 물음표로 끝), by, ask: bool, createdAt }
users/{uid}            qRemind?: bool(기본 true) · qPartner?: bool(기본 true)
```
- **답을 사람마다 문서로 나누는 이유**: Firestore 규칙은 문서 단위라, 한 문서에 둘의 답을 두면 '내 답이 있어야 단짝 답을 읽기'를 막을 수 없어요 (식단 `private/{uid}`와 같은 이유)
- 단짝이 답했는지는 `done`으로 알아요. 잠긴 답 문서를 읽으려고 하지 않기(규칙에서 거부됨)
- 답 문서는 **하나씩 get**: 목록 조회(list)는 규칙에서 막혀요
- 기본 묶음은 앱에 묶는 정적 파일 `data/questions.json` (Firestore에 안 넣음)
- 단짝이 된 날은 `couple/main`의 기념일 값 (저장소 필드 이름 그대로). 「단짝이 된 날 = 1일」 셈은 머리말 칩과 같아야 함 → 저장소 함수가 있으면 `reference/src/kst.js`의 `ddayCount` 대신 그걸 쓰고 시험 Q-K1로 확인

## 4. 그날 질문 정하기
### 언제
1. **앱에서 질문 화면이나 입구를 처음 그릴 때**: `qdays/{오늘}`이 없으면 만듦
   - 지난 `qdays` 전체(필드 q · src · skipped · date만)와 `ourQuestions`를 읽고 `pickQuestion()` → 트랜잭션으로 `get` 후 **없을 때만** `set`
   - 두 기기가 동시에 만들어도 같은 기록이면 같은 결과(순수 함수, Q-P16). 트랜잭션은 덮어쓰기만 막음
   - 기록이 1,000일을 넘어 읽기가 무거워지면 요약 문서로 바꾸기(나중)
2. **저녁 9시 서버 함수**: 그때까지 없으면 같은 모듈로 만들고 알림 (8절)
- 아무도 앱을 열지 않은 날은 문서가 없고, 그날은 질문을 쓰지 않음(묶음이 아껴짐)

### 순서 (`reference/src/pick.js`)
1. **날짜 질문** (`special.js`): 첫날(기록이 하나도 없음) → 단짝이 된 날 해마다(`{years}`, 변형 3개 차례로, 2/29는 평년 2/28) → 100일 단위(`{days}`, 변형 4개 차례로, 쉼표) → 정해진 날 9개(1/1 · 3/1 · 5/5 · 6/1 · 9/1 · 10/9 · 12/1 · 12/25 · 12/31)
2. **단짝에게 묻기**: 전날까지(서울 날짜) 만든 것 중 아직 안 나온 것, 먼저 낸 것부터
3. **목록에 섞기**: 지난 2일에 `src: 'ours'`가 없을 때만, 먼저 낸 것부터
4. **기본 묶음**: 정해진 순서(`order.js`, seed `danjjakkung`)에서 **가장 오래전에 나온 것**(안 나온 것이 먼저, 「다른 질문」으로 넘긴 것은 그날 나온 것으로 침). 처음 기본 질문 14번은 가벼운 주제만. `retired` 질문은 안 나옴
- 순서는 주제가 고르게 퍼지게 섞여 있어요(같은 주제 3번 넘게 잇따라 안 나옴, Q-O2)
- 묶음을 다 돌면 처음 나온 것부터 다시 (414일 뒤). 나중 후보: 다시 나올 때 「작년 이맘때 답」 보여 주기

## 5. 다른 질문 (`swap.js`)
- 조건: **오늘 질문 · 기본/날짜 질문 · 아직 한 번도 안 바꿈 · 아무도 안 답함** — 안 되면 버튼을 숨김(F03 · F04 · F09)
- 바꾸면 늘 기본 묶음에서 다음 것. 원래 질문은 `skipped`에 넣고 「가장 오래전에 나온 것」 기준으로 맨 뒤로
- 바꾸기 전에 확인 시트(F06). 둘 중 누가 바꿔도 둘 다에게 바뀜
- 규칙도 같은 조건을 확인 (오늘인지는 기기 시계라 화면에서만)

## 6. 쪽지(답) · 잠김 · 열림
- 화면 글은 모두 '쪽지'(내 쪽지 · 단짝의 쪽지 · 남기기 · 펴져요). 아래 설명의 '답'은 데이터 이름(`a/{uid}`)을 따른 것
- 보기 상태 (`access.js` `viewState`): `none` 둘 다 아직 · `mine` 나만 · `theirs` 단짝만(잠김) · `both` 둘 다
- **남기기**: 한 batch로 `a/{내 uid}` 만들기(`at` = serverTimestamp) + `qdays/{date}.done.{내 uid}` = serverTimestamp. 규칙이 둘이 함께 오는지 확인
- 남기면 곧바로 단짝 답 문서를 get해서 열어 보여 줌(theirs → both)
- **고치기**: 내 답만, `editedAt` 붙음 → 화면에 「· 고침」. 고쳐도 알림 없음, `done` 그대로
- **지우기 없음**
- 검사(`validate.js`): 앞뒤 빈칸 지우고 1~300자. 문구는 `text.js`
- **늦게 답하기**: 지난 질문에서 내가 아직 안 답한 날(F11 「늦게 남기기」). 같은 방법으로 남김, 알림은 안 감
- **꿍 보내서 알려 주기**(F03): 지금 있는 꿍 보내기를 그대로 부름(새 기능 아님)
- **마음에 남아요**: 둘 다 답한 날, 단짝 답 칸 아래 알약 버튼. 다시 누르면 지움. `likes.{내 uid}`

## 7. 우리가 넣는 질문
- 질문 넣기 시트(F07): 글 2~60자(물음표 없으면 붙여 줌), 기본 묶음 · 이미 넣은 질문과 같으면 거부(띄어쓰기 · 끝 문장 부호 무시)
- **단짝에게 묻기**: 내일 질문으로 (오늘 만든 건 오늘 안 나옴). 여럿이면 먼저 낸 것부터 하루에 하나
- **목록에 섞기**: 며칠 안에(2일 간격 규칙) 섞여 나옴
- 둘 다 답하는 질문(낸 사람도 답함). 그날 질문 카드에 「○○이 낸 질문」(조사: `iga()`), **다른 질문으로 못 바꿈**
- 우리가 넣은 질문 화면(F12): 기다리는 질문 / 나온 질문. **단짝이 넣은 기다리는 질문은 글을 숨기고** 「단짝이 준비한 질문이 있어요 · 내일 나와요」 (데이터는 둘 다 읽을 수 있음 — 화면에서만 숨김)
- 고치기 · 지우기: 낸 사람만, **아직 안 나온 질문만**(`canEditOurs`). 나온 질문의 글은 `qdays/{date}.text`에 따로 남아 있어 기록은 안전

|---|---|---|
| `questionDaily` | 매일 21:00 (Asia/Seoul) | `qdays/{오늘}`이 없으면 만들기(공용 `pickQuestion`, 트랜잭션) → `reminderTargets()`(안 답함 · `qRemind !== false`)에게 제목 = 이름(`T.name`), 본문 = 그날 질문 |
| `questionAnswered` | `qdays/{date}/a/{uid}` 만들어질 때 (고치기 X) | `answerPush()`: 오늘 질문일 때만, 단짝(`qPartner !== false`)에게 첫 쪽지면 `T.pushPartnerAnswered`(「단짝이 쪽지를 남겼어요 · 내 쪽지를 남기면 펴져요」), 두 번째면 `T.pushBothOpen`(「단짝도 쪽지를 남겼어요 · 서로의 쪽지를 펼쳐 볼 수 있어요」) |
- 누르면 질문 화면으로: 지금 방식(`?tab=…` → 서비스워커 → `setTab()`)에 `open=question`을 더해 주세요
- 알림 시트(F13): 지금 줄 아래 이름 묶음 두 줄(`T.settingRemind` · `T.settingPartner`). 스위치는 `users/{uid}.qRemind` · `qPartner`
- 알림 글에 **답 내용은 넣지 않음**(잠김 규칙과 맞추기)

## 9. 입구 (E1)
- 「전체」 탭 우리 기능 2칸에서 **짝꿍 식탁 카드 자리**에 넣어요 (E1-all-tab)
- 카드: 이름 + 작게 접은 쪽지 표시(34×24, `--tint` 바탕 + 단짝 색 띠) · 그날 질문 두 줄(넘치면 …) · 두 사람 점(채움 / 빈) + 상태 글
- 상태 글: `none` 「둘 다 아직이에요」 · `mine` 「단짝 쪽지를 기다려요」 · `theirs` 「단짝이 남겼어요」 · `both` 「둘 다 남겼어요」 (`text.js`)

## 10. 결산 카드 8 교체
- `결산` 넘기기(`docs/recap/`)의 카드 8 「짝꿍 식탁」 자리를 이 기능으로(머리 = 이름) (`reference/src/recap.js` `questionRecap`)
- 숫자: 그 기간 질문 수 · 둘 다 답한 날 · 우리가 낸 질문 수. 질문이 하나도 없던 기간은 카드 건너뜀(다른 카드와 같은 규칙)
- 마음에 남은 답: 둘 다 「마음에 남아요」를 누른 날 → 한쪽만 누른 날, 같으면 최근. 답 글은 서버(`monthlyRecap`)가 `a/{uid}`를 읽어 `recaps` 문서에 함께 저장 (결산 뒤에 고쳐도 그대로)
- 연말: 같은 계산을 1년으로. 1월 1일 질문(「올해 같이 꼭 해 보고 싶은 것」)의 답을 연말 카드에 넣는 건 나중 후보

## 11. 보안 규칙 (`rules/question.rules`)
- `qdays/{date}`: members 읽기. 만들기는 빈 `done · likes · skipped`로만. 고치기는 세 가지뿐 — 다른 질문(5절 조건) · 내 `done` 표시(같은 batch에 내 답 문서가 있어야) · 내 `likes`(둘 다 답한 뒤). 지우기 없음
- `a/{uid}`: **get = 본인이거나 내 답 문서가 있을 때**, list 거부. 만들기 · 고치기 = 본인만, 1~300자, 고칠 때 `at` 그대로 + `editedAt`. 지우기 없음
- `ourQuestions`: members 읽기, 만들기 = `by`가 나, 2~60자. 고치기 · 지우기 = 낸 사람만
- ⚠ 기획 계정에서는 에뮬레이터를 못 돌렸어요. **Q1에서 `rules/rules.test.mjs` R1~R12를 먼저 통과**시켜 주세요. 저장소 규칙 문법과 다르면 뜻을 지키며 고치고 `## 바뀐 것`에 적기
